# 美国出口自动更新设计（已获实施授权）

日期：2026-10-09。依据：当前 GitHub main d2d8021、上游原始源码 a8ab111，以及现有区域策略和管理页面。本文件是设计稿，不代表功能已实现或已部署。

## 目标和范围

- 继续使用现有 naiops-us-github 项目、us.naiops.ccwu.cc、ADMIN 和 KV。
- 默认美国。美国节点仅使用最近检测通过的美国出口；失败时只尝试美国备用，全部不可用就断开。
- 其他已配置区域仅在用户明确选择后使用，同样按所选地区验证，不自动跨区。
- 出口候选和可用状态自动更新；客户端继续使用原来的域名与 region=US 订阅路径，不必随出口 IP 变化逐个修改节点。
- 第一阶段保持当前域名入口和 VLESS/SS 原生订阅，不扩大到随机入口测速、额外协议或账号登录自动化。

## 上游机制与接入位置

上游的生成随机IP函数从运营商 CIDR 列表随机取地址，主要解决到 Cloudflare 的入口。订阅还支持 ADD.txt、优选 API、外部订阅；带 proxyip=true 的候选可以被写入节点路径。实际代理层从默认反代、环境变量或节点路径获得 ProxyIP，再解析 DNS TXT/A/AAAA，并尝试拨号；某些配置允许失败后直连。

我们保留上游原始源码，继续用生成脚本接入独立策略。现有区域限制、禁止任意 ProxyIP 覆盖、禁止直连兜底和 TCP-only 规则继续执行。新增出口发现和验证仅改变区域池的来源与有效性检查。

## 候选发现

美国第一阶段提供一个内置来源标识：cmliu-us-dns，对应 proxyip.us.cmliussss.net；通过固定 HTTPS DoH 服务解析 A/AAAA。该来源是候选提供者，名字中的 US 不作为国家证明。

候选来源与面板手工 IP 合并、去重。只接受公共地址与允许的端口；拒绝私网、回环、链路本地、未指定地址和格式不合法的地址。不允许公开请求传入任意来源 URL 或探测目标。

每次保留最多 32 个候选，实际探测最多 4 个，优先复查当前主出口，其余轮换，避免总是只检查 DNS 返回的前几个。第一阶段探测端口固定 443。

其他地区先保留手工候选，后续有经过确认的来源再增加，避免拼接不存在的区域来源域名。

## 出口验证

在实际 Cloudflare 运行环境中连接候选 IP:443，以固定探测域名建立 TLS，校验证书链和主机名，再请求 Cloudflare trace。必须取得有效 HTTP 200、出口 IP 和与所选区域一致的 loc，才能加入有效池。

记录候选地址、实际出口地址、检测国家、响应时间、检测时间和失败原因。候选 IP 与出口 IP 不必相同，IPv4 候选可能产生 IPv6 出口。

实现前先进行最小运行验证，确认当前 Cloudflare 环境的原生 TLS 客户端能指定 SNI 并验证证书。优先使用平台支持的标准接口，不增加第三方依赖；不复用上游只检查证书存在的简化 TLS 客户端作为可信国家检测。原生能力不符合要求时停止该实现路线，不关闭证书验证来绕过。

国家是探测服务对当次出口的判定，不能证明 IP 的永久国家，也不能保证不同目标始终使用同一出口。面板用“最近检测为美国”表述，完整客户端链路另行验收。

## 刷新、缓存和资源预算

- 默认刷新间隔 15 分钟，验证有效期 30 分钟。
- 已认证的管理、订阅请求，以及协议认证成功后的新 TCP 连接可以触发刷新。未知 UUID、未登录和无效订阅 token 的请求不得触发探测。
- 缓存有效且未到刷新时间，直接使用；到刷新时间但缓存仍有效，允许有请求生命周期支持的后台刷新；缓存已过期或首次启动，必须等待有限时长的刷新，失败则拒绝连接。
- 每次探测最多 4 个候选、并发最多 2；单候选最多 4 秒，发现及整次刷新总时限 12 秒。超时必须关闭本次探测 socket，清理计时器。
- 有效池最多 8 个出口。失败来源不得将未经验证的候选写入有效池，也不得延长旧验证时间。
- 缓存键包含访问域名、Cloudflare 机房、区域和来源/手工配置摘要，避免不同环境、机房或配置串用结果。同一实例共享一次在途刷新；不声称 KV 能提供跨实例的全局锁。
- 配置变更改变缓存摘要，旧池不再作为新配置的有效结果。
- 自动是“有请求时按间隔更新”，无请求时不刷新。保持现有 Pages 项目，不为了定时任务创建新 Worker，也不向 GitHub 保存 Cloudflare Token。

这些数值是初始预算，须在目标运行环境验证 CPU、连接数与响应时间；若不满足免费额度或平台限制，先减小探测规模，不自行升级付费或放宽预算。

## 主备与登录稳定性

当前主候选仍在近期验证通过的所选区域内，就保持它在首位。刷新主要补充和剔除备用，不因轻微测速差异频繁换主出口。原主候选已失效、验证过期或国家变化，才选择该区的其他有效候选。

拨号失败按有效池顺序尝试备用。检测结果过期、国家未知、全部失败时关闭连接，不直连、不跨区。Mihomo 保留当前区域的 VLESS/SS 协议切换。

不向无法验证的旧连接热切换出口；当前设计约束新连接，已经建立的 TCP 连接维持至关闭。多个 Cloudflare 机房和 KV 传播无法保证全球所有连接永远共用一个主 IP，不能据此宣称账号会话完全稳定。

ChatGPT HTTP 403 单独显示为目标站点问题，不盲目重放登录请求或循环换 IP；免费出口是否被目标接受仍需人工登录验收。

## 面板和存储

在现有区域页面增加：自动发现开关、来源选择、手工候选输入、立即刷新、上次检测时间，以及候选/有效/失败列表。美国默认启用内置来源；面板中的手工地址也是待验证候选。

管理员配置继续独立存储；自动检测结果使用单独 KV 键，不写入 UUID、密码或订阅凭据。保留并读取旧 version=1 区域配置，升级后的保存采用明确的新版本，不在读取时偷偷覆盖旧配置。

立即刷新沿用现有 ADMIN 登录、同源 JSON 校验和最少 60 秒的操作间隔。公开订阅返回区域节点，不包含管理凭据和内部错误详情。

## 上游同步和发布

新增逻辑留在 policy 来源文件，生成脚本只增加必要的认证后出口解析接入点。上游源码、许可证和版本锁继续保留。锚点变化、新增实际代理入口或测试失败时停止同步并报告，不覆盖定制 main。

候选池刷新是运行时数据更新，不触发代码发布。GitHub 测试与打包继续不需要 Cloudflare Secret；正式代码发布仍使用用户逐版本授权和现有项目。

## 验收顺序

1. 最小目标环境实验：真实证书验证成功；错误主机名和无效证书拒绝；trace 有明确国家和出口。
2. 回归：US 接受、非 US/未知国家拒绝、发现源失败、缓存过期、配置变更、认证前不探测、同实例刷新合并、超时清理，以及区域内切换和禁止直连/跨区。
3. 面板操作：旧配置加载、开关保存、立即刷新、状态回读、订阅保持 region=US；配置损坏时明确报错。
4. 同步与打包：现有测试和新增测试通过，原始上游来源及生成一致性通过，发布包对应确切 main 提交。
5. 同一项目的隔离预览验证 VLESS/SS 实际路径和近期美国检测，再按已授权的版本发布到生产；预览与生产检测缓存隔离。
6. 生产回读 release SHA、域名与绑定，验证真实 VLESS/SS 美国出口。账号登录由用户操作，单独记录结果。
