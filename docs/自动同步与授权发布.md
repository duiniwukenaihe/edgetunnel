# 自动同步、测试与手动发布

`main` 是我们的定制版本，默认美国并由管理面板维护其他地区。发布目标保持现有 **naiops-us-github**，域名 **us.naiops.ccwu.cc**；不新建项目、不迁移域名。

## 日常更新与测试

每天北京时间约 08:20，Sync upstream into custom main 校验当前 main，获取 cmliu/edgetunnel 的明确提交，仅导入原始 worker，重应用本地策略并运行全部回归。成功后无强推地原子更新 upstream-candidate 和 main。同步只更新 `_worker.js`、`upstream/_worker.js` 和 `upstream/version.json`，不覆盖策略、页面、文档或工作流。

上游结构不兼容、许可证变化、测试失败或 main 同时被修改时停止。计划任务可能延后；没有上游更新不产生提交。同步不会自动触发发布，也不会向 Cloudflare 上传。

GitHub → Actions → Naiops CI 查看 PR/main 测试，也可手动 Run workflow。Sync upstream into custom main 可手动触发同步；失败的候选 patch 作为附件保留 7 天。

本地修改 `policy/regions.js`、`policy/regions.html` 或生成脚本后：

```sh
python3 scripts/apply-us-policy.py upstream/_worker.js _worker.js
bash scripts/verify.sh
```

## 默认发布：不配置 Cloudflare 密钥

1. 打开 [Prepare release (manual)](https://github.com/duiniwukenaihe/edgetunnel/actions/workflows/deploy.yml)。
2. 点击 Run workflow，选择 main。revision 留空使用本次运行的 main 提交；也可指定曾进入 main 的完整 40 位 SHA。
3. 等待 prepare 成功。deploy 在默认关闭的开关下显示 skipped，这是正常结果，不表示打包失败。
4. 在该次运行的 Artifacts 下载 `naiops-release-提交编号`。外层下载包包含 assets/、`naiops-us-pages.zip` 和 `release-manifest.json`。先解开外层包，**只把里面的 naiops-us-pages.zip 作为部署文件**。
5. 登录 Cloudflare → Workers & Pages → naiops-us-github → Create a new deployment → Production。上传部署 ZIP；核对版本清单后，你点击 Save and Deploy，这就是本次发布授权。
6. 发布完成后访问 `https://us.naiops.ccwu.cc/healthz`，确认 status=ready 且 revision 等于清单中的 revision；随后检查密码登录、区域页面和真实客户端。

不能使用 GitHub 的 Download ZIP、上游 main.zip 或整个外层 Artifacts ZIP 代替部署包。包已经把准确提交写入 worker，包含 Pages 需要的根目录 `_worker.js` 和 `_routes.json`。main 后续变化不会改变下载包。

当前项目支持直接上传 `_worker.js`，见 [Cloudflare 官方说明](https://developers.cloudflare.com/pages/get-started/direct-upload/)。已有生产 ADMIN、HOST、KV 绑定保留；上传源码不能代替环境绑定。KV 区域设置与 GitHub 发布授权是两回事。

## 可选自动上传

仅当主动决定让 GitHub 上传时，才需要专用 Cloudflare API Token；无需为了测试或下载包配置它。默认 CLOUDFLARE_DEPLOY_ENABLED=false，GitHub 不保存 Cloudflare 密钥。

可选启用方法：在 Settings → Environments → cloudflare-production 的 Environment secrets 添加 CLOUDFLARE_API_TOKEN，再将仓库变量 CLOUDFLARE_DEPLOY_ENABLED 设为 true。按[官方 Pages CI 权限](https://developers.cloudflare.com/pages/how-to/use-direct-upload-with-continuous-integration/)限定账户 Pages 编辑权限；这通常仍能管理该账户的其他 Pages 项目，不是单项目权限。

每次仍要手动启动同一发布流程；prepare 完成后，deploy 等待 duiniwukenaihe 在 Review deployments → Approve and deploy 批准。保护环境只允许 main，禁止管理员跳过。普通测试和 prepare 不读取该密钥。Token 不放 KV、源码或订阅，不使用 Global API Key。

可选自动发布使用固定 Wrangler 4.147.0 上传到 naiops-us-github，自动检查准确上线 SHA。手工上传需要自己检查 /healthz，不能把准备 job 成功当成线上已更新。

## 区域版本的验收

新版本登录后从 `/admin` 进入 `/admin/regions`。默认只有美国；添加真实地区出口，保存后更新客户端订阅。KV 跨机房传播可能延后，已有连接不迁移。未知或被删除地区拒绝连接，全池失败不跨区或直连。

自动回归和本地页面检查证明代码行为，不证明所有地区地址真实可用、出口永久位于指定国家、客户端实际故障切换或 ChatGPT 登录成功。2026-10-09 的线上旧版本 VLESS/SS 曾实测 US、TLS 和 HTTP 200；本次区域版本尚未上线。程序探测 ChatGPT 曾返回 403，账号登录需真实验收。
